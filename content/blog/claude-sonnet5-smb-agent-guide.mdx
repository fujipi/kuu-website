「AIエージェントを作りたいが、どのモデルを使えばコストが読めるのか分からない」——エンジニア数名規模の中小企業でこの壁にぶつかることは珍しくありません。Claude Sonnet 5は、この判断を変えるモデルです。[Claude Agent SDK](/blog/claude-agent-sdk-minimum-implementation-smb/)で実装を始める前に、モデル自体の特性とコスト構造を押さえておきましょう。

## Claude Sonnet 5とは何か

> Claude Sonnet 5はOpus 4.8に迫る性能を、Sonnet価格帯のまま2026年6月に公開した。

Claude Sonnet 5は、計画立案・ツール使用・コーディングを自律的にこなす「最もエージェント的なSonnetモデル」として公開されました。前世代のSonnet 4.6が完了できなかった複雑なタスクをやり切り、指示しなくても自分の出力を検証する挙動が確認されています。性能面ではOpus 4.8に近い水準に達しながら、価格はSonnet系に据え置かれている点が中小企業にとっての最大の意味です。「精度を取るか、コストを取るか」の二択だった判断が、Sonnet 5では両立しやすくなりました。

## 1Mトークンの文脈窓は何に使えるか

> Claude Sonnet 5は1Mトークンの文脈窓をAPI・Bedrock・Vertex AIで標準搭載する。

Claude Sonnet 5はClaude API・Amazon Bedrock・Google Cloud・Microsoft Foundryのいずれでも1Mトークンの文脈窓を標準で使えます。ベータヘッダーは不要で、長文脈リクエストも通常料金のまま処理され、1リクエストの最大出力は128kトークンです。中小企業の実務では、契約書や仕様書一式を横断チェックする、複数の議事録を1回のリクエストで要約するといった用途で効果を発揮します。ただしトークン数が増えるほど精度が落ちる「コンテキスト腐敗」が知られているため、渡す情報を絞り込む設計判断も必要です。

さらにSonnet 5は「コンテキスト認識」機能を持ち、会話の残りトークン予算をモデル自身が把握しながら長時間タスクを進めます。現在の文脈窓サイズと残量がシステムプロンプトやツール呼び出し後に自動注入される仕組みで、開発者側で明示的に管理する必要はありません。

## エージェント開発でどうコストを抑えるか

> Sonnet 5は2026年8月31日まで$2/$10、以降は$3/$15の価格に切り替わる。

価格は2026年8月31日までが入力$2・出力$10（100万トークンあたり）、それ以降は入力$3・出力$15に切り替わります。中小企業がこの価格帯を活かすには、[プロンプトキャッシュ](/blog/prompt-caching-agent-design-context-reuse/)の併用が要点です。同じシステムプロンプトやツール定義を繰り返し送るエージェントでは、キャッシュ読み取り価格が通常入力の約1割まで下がり、TTL内で3回以上再利用する構成にするだけで実効コストが変わります。Sonnet 5は「エフォートレベル」も選択でき、定型対応はエフォートを抑え、複雑な判断が必要な処理だけ引き上げる使い分けが現実的です。

## 中小企業はどう導入を始めればよいか

> 定型業務から着手し、プロンプトキャッシュとエフォートレベル調整で月次コストを見積もるのが現実的だ。

いきなり全社導入を狙うのではなく、問い合わせ対応や社内文書の要約など、失敗しても影響の小さい業務から始めるのが現実的です。導入初期は次の3点を確認してください。

1. **対象業務の文書量**: 1Mトークン文脈窓が本当に必要か、通常のRAG構成で足りるか
2. **繰り返し呼び出しの有無**: 同じシステムプロンプトを何度も送る構成なら、プロンプトキャッシュ導入の優先度が高い
3. **精度要件**: 定型業務はエフォートを抑え、契約書レビューなど高精度が必要な業務だけエフォートを引き上げる

## まとめ

Claude Sonnet 5は、1Mトークンの文脈窓と導入価格の組み合わせで、中小企業がエージェント開発に着手しやすいモデルです。要点は3つです。

1. **性能とコストの両立**: Opus 4.8に迫る性能をSonnet価格帯で使える
2. **文脈窓の使いどころ**: 1Mトークンは長文書横断チェックに有効だが、渡す情報は絞り込む
3. **コスト管理**: プロンプトキャッシュとエフォートレベルの調整で実効コストを抑える
